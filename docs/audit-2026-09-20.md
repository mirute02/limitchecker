## 追加監査（公開後、検査手法の見直し）

初回監査のパターンに **PCRE 構文（`\s` `\b` 否定先読み）が混ざっており、
POSIX 拡張正規表現では解釈されず、一部の検査が実際には動いていなかった。**
`\s` を使った検査は 0 件、`[[:space:]]` に直すと 34 件ヒットした。
Tailscale アドレスの検査も `\b` を使っていたため同様に無効だった。

**検出器そのものの動作を、必ず存在する文字列で毎回確かめる**手順に改めて、
公開済みリポジトリを新規 clone して検査し直した。

### 検査範囲

| 対象 | 範囲 |
| --- | --- |
| ブロブ | 111 個（全25リビジョン、到達不能オブジェクトを含む） |
| ファイル形式 | 検査時点では全ファイルがテキスト（**下記の訂正を参照**） |
| コミットメッセージ | git grep はファイルしか見ないため別途走査 |
| リモートの実体 | GitHub API で直接確認 |

### 結果

- **秘密に関わる代入を全件列挙して目視**（`token` `password` `secret` `api_key`
  `credential` `private_key` `bearer`）。すべて変数・引数・空文字・キー名・
  生成コマンドで、値の直書きは 0 件
- **エントロピー検査**（4.0 bit/文字以上・24文字以上）で 9 件ヒット。
  すべて読める形のパスや識別子。ランダムな秘密は 0 件
- メールアドレス: ファイル内 0 件。コミットメタデータに noreply 2種のみ
- Tailscale アドレス: 0 件
- `.env` / `local.properties` / `google-services.json`: リモートに存在しないことを
  GitHub API で確認

### 教訓

`grep -E` で `\s` `\b` `\d` `(?!)` は使わない。POSIX 文字クラスを使う。
そして**検出器が動くことを確認していない「0 件」は、結果ではない。**

## 訂正（独立監査の指摘による）

上の「全ファイルがテキスト。バイナリによる検査の死角はない」という記述は、
**公開時点で既に事実と異なっていた。**

検査そのものは clone した時点の内容に対して正しかったが、その結果を記録した
コミット（3da8279）を `git add -A` で作った際に、**まだ組み込んでいなかった
アイコンの PNG 15枚を巻き込んでいた**。つまり「バイナリはない」と書いた
コミット自身がバイナリを追加している。

PNG 15枚は独立監査で改めて検査され、`IHDR` / `IDAT` / `IEND` のみで
テキストチャンク（`tEXt` / `zTXt` / `iTXt`）も IEND 以降の付加データもなく、
埋め込みの痕跡はないことが確認されている。結論は変わらない。

### 教訓

- **`git add -A` は作業中の未追跡ファイルまで巻き込む。** 監査のように
  「その時点の状態」を記録するコミットでは、対象を明示して add する
- 検査結果を書いた文章は、**その文章をコミットした時点でも正しいか**を確かめる。
  検査時点で正しかったことは、公開時点で正しいことを意味しない

## `\b` と `\s` の扱いについて（決着）

対照試験で確認した挙動:

| | `\b` | `\s` |
| --- | --- | --- |
| `git grep -E` | **効かない**（127.0.0.1 の検出が 0 件 vs POSIX 版 8 件） | 効かない |
| スタンドアロンの `grep -E`（本環境は ugrep） | 効く | — |

つまり初回監査の Tailscale 検査（`git grep` + `\b`）は無効だった。
POSIX 構文で再検査し、0 件であることを確認済み。

`.githooks/pre-commit` の Tailscale 検査も `\b` を使っていた。本環境の grep では
動作していたが、macOS / BSD の grep では保証がないため POSIX 構文に直した。
公開リポジトリとして、他の環境でフックが黙って無効になる状態は避ける。
修正後、4種の検出器すべてが発火することを対照試験で確認した。

## 独立監査 2本目: 個人情報

**結論: 個人情報の観点では公開して問題ない。**

実名・実メール・電話番号・住所・内部 IP（Tailscale CGNAT / RFC1918）・端末シリアル・
IMEI・ANDROID_ID・MAC アドレス・セッション ID・作業ディレクトリの絶対パス・
スクリーンショットのいずれも、全リビジョン・全ブロブ・全コミットメタデータに存在しない。

26 種のパターンそれぞれにカナリア文字列を与えてマッチを検証したうえで実施。
実際に IPv6 のパターンが `::` 圧縮形を拾えず自己テストで落ち、修正してから走らせている。
コード側の自動収集（`gethostname` / `Build.SERIAL` / `ANDROID_ID` 等）も 0 件で、
agent の送信内容はホワイトリストのみであることが確認された。

### 指摘を受けて直したもの

**`.githooks/pre-commit` の shebang が Termux 固有のパスだった。**
README は `git config core.hooksPath .githooks` を案内しているが、
**Mac / Linux ではインタプリタが見つからずフックが起動しない**状態だった。
公開しているセキュリティ機構が、案内どおりに設定しても黙って無効になっていた。

実測して両環境で動く形を選んだ:

| shebang | この端末（Termux） | Mac / Linux |
| --- | --- | --- |
| `#!/data/data/com.termux/files/usr/bin/bash` | 動く | **動かない** |
| `#!/usr/bin/env bash` | **動かない** | 動く |
| `#!/bin/sh` | 動く | 動く |

`#!/bin/sh` を採用し、bash 固有の `${var:0:n}` も POSIX に書き換えた。
修正後、4種の検出器すべてが発火し、許可ドメインのメールは誤検出しないことを確認。

**`deploy/termux-boot-hub.sh` がリポジトリの場所を決め打ちしていた。**
スクリプトの位置から辿るようにし、`LIMITCHECKER_REPO` でも指定できるようにした。

**「勤務先メール」という表現**を「実際のメールアドレス」に言い換えた。
作者が被雇用者であることを不必要に示すため。

### 受容した指摘

- **全コミットの `Co-Authored-By: Claude`**: AI を使って書いたことと、
  利用しているモデルが読み取れる。既に公開済みで、消すには履歴書き換えが必要。
  透明性の観点ではむしろ残すほうが誠実なため、現状維持とする
- **作者の環境構成**（Mac + Linux GPU 機 + Android/Termux）が設計書から読み取れる。
  設計の前提として必要な記述であり、個人特定には至らない
- **タイムスタンプが全て +0900**。修正不能。リスクは低い

### 検査手順の欠陥を1つ修正した

APK の検査で、**ダウンロードに失敗してファイルが無いのに「OK」を出していた。**
対照試験の結果が 0 件だったにもかかわらず「検査は動作している」と無条件に
表示する書き方になっていたため。

**対照試験は、結果を見て分岐しなければ意味がない。** 0 件なら
そこで止めて「結論を出せない」と言うべきだった。手順を直し、
対照が 0 件なら検査を中止するようにした。

これで**同じ型の誤りを3回踏んだ**ことになる（PCRE 構文で 0 件、
ブロブ数の記述、今回）。共通するのは「確認したつもりで確認していない」こと。
