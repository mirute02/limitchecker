# 決定事項（設計書からの変更点）

[docs/design.md](design.md) を基準に、検討の結果変更した点を記録する。
設計書自体は当初の記録として書き換えない。

## D1. 残量が古いときはグレーアウトして「更新できません」と出す

**決定**: statusLine は Claude Code の実行中しか更新されないという制約を、そのまま受け入れる。
値が古ければ薄く、さらに古ければグレーにして、取得できていないことを明示する。

**理由**: 定期的に残量を取得する手段が存在しないため。`claude` CLI に usage 相当の
サブコマンドはなく（確認済み）、定期取得するにはアプリ側が資格情報を持つ必要がある。
正確さのために資格情報を抱えるより、取れないときに正直にそう表示するほうが、
公開リポジトリとして筋が良い。

**波及**: アプリが独自にアカウントへログインする案を破棄。
アプリが保持する秘密は hub のトークン1つのままになる。

## D2. 公式アプリからは取得しない（不可能）

**決定**: Claude / ChatGPT の公式 Android アプリからは残量を取らない。

**理由**: Android のアプリサンドボックスにより、非 root 端末では他アプリのデータ領域を
読めない（実機で `/data/data/` が Permission denied、root なしを確認）。
アクセシビリティサービスで画面を読む手段は技術的には残るが、全画面の内容を読む権限を
要求するため、本リポジトリのセキュリティ方針と衝突する。

## D3. Android 側に CLI を必要としない

**決定**: Android アプリは hub へ HTTP で問い合わせるだけとし、
Claude Code CLI も Termux も前提にしない。

**理由**: 表示端末に開発環境を要求しないため。CLI が動くのは、もともと作業している
Mac / Linux のみ。Termux は APK のビルドにのみ使う。

## D4. FCM を使わず、常設通知の前景サービスがロングポーリングする

**決定**: 設計書の段階4（FCM）を置き換える。通知領域に常設する通知を出し、
その前景サービスが hub をロングポーリングして即時性を確保する。

**理由**: 常設通知には前景サービスが必要で、常駐しているなら FCM は要らない。
FCM は停止中のアプリを起こすための仕組みであるため。
Firebase プロジェクト、`google-services.json`、トークン管理がまるごと不要になる。

**波及**: ステータスバー（時計・電池の行）には、実行時生成したアイコンで
最も逼迫しているリングの残量を数字で出す。
ただし小アイコンは OS がモノクロに塗るため、色分けはシェードを開いた先で見せる。

## D5. 作業ディレクトリはフルパスを送らない

**決定**: イベントに乗せる作業ディレクトリは basename のみ。送らない設定も用意し、
フルパスを送る選択肢は実装しない。

**理由**: フルパスはユーザ名・顧客名・案件名を含む。[security.md](security.md) 参照。

## D6. アカウントの同定はユーザが宣言したラベルで行う

**決定**: メールアドレスや組織 ID ではなく `LIMITCHECKER_CLAUDE_ACCOUNT` 等のラベルで
マシンを突き合わせ、同一アカウントの残量を1組に畳む。

**理由**: 個人情報を送らずに済み、仕事用と個人用の併用も表現できる。

**注意**: 同一アカウントの値は**合算しない**。枠は共有なので各マシンは同じ値を報告する。
取得時刻が最も新しいものを採用する。

## D7. リングは2周にする

**決定**: 設計書の三重ドーナツを二重にする。外側が5時間枠、中央が週次枠。

**理由**: statusLine の `rate_limits` は `five_hour` と `seven_day` の2つのみで、
内側リングに想定していたモデル別週次枠が存在しない（[findings-statusline.md](findings-statusline.md)）。
週次枠そのものは全モデル合算で取得できるため、残量把握という目的は2周で達成できる。

実在しないデータのために「今日の消費量」や「コンテキスト残量」を内側に充てる案は見送る。
前者は残量ではなくリングの意味が混ざり、後者はセッション単位の値でアカウント単位の
外側・中央と層が食い違うため。

## D8. ドーナツ中心にはリセット時刻を置く。常に5時間枠

**決定**: 中心に「5時間枠の残%」と「5時間枠のリセットまでの残り時間」を置く。
逼迫している枠に応じて切り替えることはしない。

**理由**: 中心の意味が固定されるので読み違えない。
「今から長い作業を始めてよいか」に直結するのは5時間枠のほうであり、
これは本ツールが解決したい困りごとそのもの。

週次枠が逼迫した場合は中央リングの色（50%超=緑 / 20〜50%=黄 / 20%未満=赤）で気づける。
中心を切り替えなくても取りこぼさない。

**波及**: 設計書は「リセットまでの残り時間はリングの下に小さく添える」としていたが、
中心に移すことでリングの下が空き、マシンチップを置く余地ができる。
API 仕様の変更は不要（`resets_at` は既に各リングに含まれる）。
