# セキュリティ / プライバシー方針

本リポジトリは最終的に GitHub で公開する。当面は private だが、**private → public の切り替え時に
git 履歴の全コミットがそのまま公開される**ため、「公開直前に掃除する」方式は成立しない。
1コミット目から本方針を適用する。

万一コミットしてしまった秘密は、履歴を書き換えても漏れたものとして扱い、必ず再発行する。

## 1. リポジトリと APK に入れないもの

| 対象 | 理由 |
| --- | --- |
| hub の認証トークン | これ1つで全マシンの状態を読める |
| Tailscale のアドレス・ホスト名 | 内部ネットワーク構成の露出 |
| マシン名の実値（設定例を除く） | 所属や環境の推測材料になる |
| 署名鍵 (`*.jks` / `*.keystore`) | 同一パッケージ名の偽アプリを配布可能になる |
| `google-services.json` 等 | プロジェクト ID と API キーを含む |
| statusLine / フックのキャプチャ結果 | セッション ID と作業ディレクトリを含む |
| 作業マシンの絶対パス | ユーザ名・顧客名・案件名が混ざる |

実値はすべて `.env`（gitignore 済み）に置き、リポジトリには `.env.example` のみ置く。

コミットメールは GitHub の noreply アドレスを使う（本リポジトリの `user.email` に設定済み）。
勤務先メールを履歴に残さないため。

## 2. 収集データの最小化

このアプリは「残量」と「エージェントが止まっているか」だけを知りたい。
それ以上は取得しない。設計上の不変条件として扱う。

- **会話内容は一切読まない・送らない。** `~/.claude/projects/**/*.jsonl` を読む場合も
  集計値のみを取り出し、本文・プロンプト・ファイル名を hub へ送らない
- **作業ディレクトリはフルパスを送らない。** 既定は basename のみ
  （`<ホーム>/clients/<顧客名>/repo` → `repo`）。送信しない設定も用意する
- **セッション ID は hub 内部のキーに留める。** 通知本文やウィジェットに表示しない
- **マシン名はユーザが設定した短いラベルのみ。** ホスト名を自動取得しない

## 3. hub 実装ルール

- **待ち受けアドレス**: 既定 `127.0.0.1`。Tailscale アドレスは明示設定時のみ。
  `0.0.0.0` はコード側で拒否する（設定ミスによる全世界公開を防ぐ）
- **認証**: 固定トークンを `Authorization` ヘッダで受ける。比較は `hmac.compare_digest`
  で定数時間比較する（タイミング攻撃対策）
- **既定トークンを持たない**: 未設定なら起動を拒否する。「とりあえず動く」状態を作らない
- **ログ**: `Authorization` ヘッダとトークンを出力しない。リクエストボディもそのまま出さない
- **入力検証**: machine id / session id は `[A-Za-z0-9_-]{1,64}` に制限する。
  ファイル名やログに使う値なので、パストラバーサルとログ汚染を防ぐ
- **エラー応答**: 内部パスやスタックトレースを返さない

## 4. Android 実装ルール

- トークンは `DataStore` に保存し、ログに出さない
- `android:allowBackup="false"` と `dataExtractionRules` で端末バックアップ対象から除外する
- 全コンポーネントを `android:exported="false"`（ウィジェットのレシーバ等、必要なものを除く）
- 平文 HTTP は Tailscale 内に限るため `network_security_config` で接続先ホストを限定する
- スクリーンショットを課題に添付する際は、マシン名・パス・残量以外を写さない

## 5. リポジトリ運用

- `.gitignore` を先に置く（実施済み）
- `.githooks/pre-commit` で、秘密らしき文字列と絶対パスの混入をコミット前に検出する
  （`git config core.hooksPath .githooks` で有効化）
- ドキュメント・テストのサンプル JSON は合成値のみ。実機の出力を貼らない
- public 化の直前に、履歴全体を対象としたスキャンを1回実施する
